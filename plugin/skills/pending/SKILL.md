Plugin root: `${CLAUDE_PLUGIN_ROOT}`. Use this absolute path wherever shared files say `<plugin>`; the variable is not set in Bash.

You keep the user's waiting list honest: it is read from the work itself, never written by hand. The cockpit asks each job's open cards as they arrive, with steps 2 and 3 read by path (`${CLAUDE_PLUGIN_ROOT}/shared/jobs.md`, Cockpit 5); this skill is the manual and recovery view of the same list.

## Iron laws

1. The list comes from `pending.mjs`; never keep a second list by hand, because a copy drifts from the files it describes.
2. A draft leaves `plans/drafts/` only through `pending.mjs done`, after the tool that published or applied it confirms the result, or after the user drops it.
3. Archiving is local; it never publishes, pushes or changes a tracker.
4. Only the user's yes at a command's own permission prompt publishes. A timed-out, unanswered or annotated question leaves every card as it was; never take an option for the user.
5. A card's commands run only from a card under "To publish" that `pending.mjs card-start` accepted just before; a card under "Started, not closed" is never run again.

## Not this skill

Posting a review draft → `/tedy:review-pr`. Posting Doc or Figma comments or tracker drafts → `/tedy:pm`.

## Procedure

1. **List.** From the project directory: `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs list`. Quote its output; it prints `Nothing waits on the user.` when the list is empty. Cards (files in `plans/drafts/` with a `kind:` header, written by `pending.mjs card`) list under "To publish", "Questions", "For your information", "Started, not closed" and "Refused cards"; "Jobs" shows each open job with its file status, except that a running job v0.2.24 or v0.2.25 started shows `older kit`, or `older kit (session open)` while the claude session that kit recorded still runs; other drafts and stubs list as before. Done when the output is in the reply.
2. **Approve.** For `approve`, take the cards under "To publish", leaving out any marked `job running`. Each `### n` block is one command on its first line plus the text it writes: a kit publish command, or exactly `gh pr merge <n> --repo <owner/repo> --merge|--squash|--rebase`.
   - For a `preview: run` card, first `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs card-check <card>`, and only when it passes run each block's command as written (it has no `--apply`), quote its output, and make the block `<command> --apply`, plus `--lock <n>` when the output prints one (`set` does; `comment`, `relation` and `doc-comment-file post` do not), followed by the quoted lines.
   - There is no `AskUserQuestion` for a publish card (ADR 0022). Quote every block of the card verbatim, each in its own fenced block of the reply, with the card title and block number, then in the same turn run `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs card-start <card>`. It runs every `card-check` check (a refused or started card, a running job, a block that is not one allowed command, a draft whose sha256 differs from `draft-sha:`) and marks the card `status: started`, so it is never offered or run again. Then run the blocks' commands in card order; each one's permission prompt is the approval. Stop at the first block that fails or is refused (a non-zero exit or a "No" at its prompt) and never run a later block. Quote each read-back. When every block succeeded, `pending.mjs done <card>`, which also archives its `draft:` when no other card names it. A card under "Started, not closed" stays there until its read-backs are checked and it is closed with `done` or `card-note --refuse`.
   - On a "No" at a block's prompt, or a block that failed: the user's note or the failure, and which blocks already wrote (a partly published card), go into the job's note for this round, and its `card-note <card> --text "<note>; blocks <n,…> wrote" --refuse` comes only after that note went out (Round per job, step 3), so a refused rework is never stranded and the old card never runs again. A card that names no job: `card-note --refuse` it with the note and redo it in this session. To drop a card the user asks to drop: `pending.mjs done <card>`. On a `card-check` or `card-start` refusal that only says the job is still running or another live cockpit runs it, leave the card open. On any other `card-check` or `card-start` refusal, or a writer's refusal (pin, ledger or lock; a moved PR head the job carries with `draft-lint.mjs carry` and then writes a new card): before anything else `card-note <card> --text "<why>" --refuse`, and the reason goes into that job's note. Name the job or session that must redo it and which blocks already wrote.
   - Once no question or publish card names a job listed under "Jobs", run `node ${CLAUDE_PLUGIN_ROOT}/scripts/job.mjs close <job file> --if-finished` for a `done` one, which keeps a dev job whose PR is still open, and plain `close <job file>` for a `stopped` one. Both refuse and write nothing while the job's agent is still running, waiting or not yet started in a live cockpit session, or when its bound agent's record holds no cockpit pid, because any job can mark another job `done` or `stopped`. When it refuses, quote the refusal, tell the user why the job stays open, and do not close it. When it closes a job an older kit started, quote its line that the job's session is the user's to end.
3. **Questions.** Ask each card under "Questions" that is not yet shown as `(answered: …)` or `(job running)` as one question, its option lines as the options in card order (the first is the recommended one and gets `(Recommended)`) and their consequences as the descriptions. A card whose options are the `run.none`, `run.lint` and `run.all` labels is a review job's run question: ask it with header `run.header` and its question text as written, naming the one head sha, so the hook records an approving answer for that sha. When the card names a job, follow `${CLAUDE_PLUGIN_ROOT}/shared/jobs.md` Cockpit 5 and 6: a card asking to start another role's job is settled here: start it on yes, then on any answer `card-note` the label and `done` it; every other answer goes back in one note file per job, holding all of that job's answers from this round, through one `job.mjs resume` per job, in the order below. A card that names no job: `card-note` the label.
   - **Round per job.** Once this round's answers are in, take each job in turn. First run every publish card of that job the user has not held back: its `card-start` and its writes, each approved at its own prompt (step 2). Then one `job.mjs resume` per job, with one note file holding every answer, reword and refusal reason for that job, and the SendMessage or Agent call it prints. Only after that call went out, `card-note` each answered card with its label and `pending.mjs done` it, and `card-note --refuse` each reworded card. When `card-check` or `card-start` refuses only because the job is still running or another live cockpit runs it, leave the card open, so it is asked again. When `resume` prints `busy:`, leave every card of that job as it is, unanswered; when it prints `refused:`, quote it and `card-note --refuse` each unanswered card of that job with the reason; any other output leaves them (`shared/jobs.md`, Cockpit 6). Archive each card under "Answered and delivered" with `pending.mjs done`.
4. **Notices.** One `multiSelect` question listing the cards under "For your information" (up to four options per question); `pending.mjs done` each one the user picks.
5. **Done.** For `done <file>`: confirm the item was posted, sent, applied or dropped (the posting tool's output, a comment list or a tracker read-back), then `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs done <file>` and report the `archived:` path. Done when the file sits under `plans/archive/` and `MOVES.tsv` has its line.
6. **Stub.** For an item with no file and no git trace (a message the user must send, a call to make): `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs stub "<action>"`. Done when the printed file exists.

## Done

The reply quotes the current list, every archived, stubbed or noted file path is named, and every command run from a card has its read-back quoted.
