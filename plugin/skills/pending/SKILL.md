Plugin root: `${CLAUDE_PLUGIN_ROOT}`. Use this absolute path wherever shared files say `<plugin>`; the variable is not set in Bash.

You keep the user's waiting list honest: it is read from the work itself, never written by hand. The cockpit asks each job's open cards as they arrive, with steps 2 and 3 read by path (`${CLAUDE_PLUGIN_ROOT}/shared/jobs.md`, Cockpit 5); this skill is the manual and recovery view of the same list.

## Iron laws

1. The list comes from `pending.mjs`; never keep a second list by hand, because a copy drifts from the files it describes.
2. A draft leaves `plans/drafts/` only through `pending.mjs done`, after the tool that published or applied it confirms the result, or after the user drops it.
3. Archiving is local; it never publishes, pushes or changes a tracker.
4. Only an answer publishes. A timed-out, unanswered or annotated question leaves every card as it was, in `ask` mode too; never take an option for the user.
5. A card's commands run only from a card under "To publish" that `pending.mjs card-start` accepted just before; a card under "Started, not closed" is never run again.

## Not this skill

Posting a review draft → `/tedy:review-pr`. Posting Doc or Figma comments or tracker drafts → `/tedy:pm`.

## Procedure

1. **List.** From the project directory: `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs list`. Quote its output; it prints `Nothing waits on the user.` when the list is empty. Cards (files in `plans/drafts/` with a `kind:` header, written by `pending.mjs card`) list under "To publish", "Questions", "For your information", "Started, not closed" and "Refused cards"; "Jobs" shows each open job with its file status, except that a running job v0.2.24 or v0.2.25 started shows `older kit`, or `older kit (session open)` while the claude session that kit recorded still runs; other drafts and stubs list as before. Done when the output is in the reply.
2. **Approve.** For `approve`, take the cards under "To publish", leaving out any marked `job running`. Each `### n` block is one command on its first line plus the text it writes.
   - For a `preview: run` card, first `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs card-check <card>`, and only when it passes run each block's command as written (it has no `--apply`), quote its output, and make the block `<command> --apply`, plus `--lock <n>` when the output prints one (`set` does; `comment`, `relation` and `doc-comment-file post` do not), followed by the quoted lines.
   - `AskUserQuestion`, header `approve.header`, one question per block, at most four per call, each question naming the card title and the block number so no two questions in a call share text (a repeated text gets no approval); a card with more blocks takes several calls, its blocks together. Options: `approve.all`, whose `preview` is the block verbatim; `approve.reword`; `approve.hold`; `approve.drop`. Never `multiSelect`. Right before the call, with no tool call between, quote each `approve.all` `preview` verbatim in its own fenced block of the reply's last text before the call: a client that reports no preview annotations (T3 Code) gets a ticket only for a block that turn showed (ADR 0020).
   - A card runs only when every one of its blocks got `approve.all`. Then first `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs card-start <card> --approved <every block number that got approve.all, comma-separated>`. It runs every `card-check` check (a refused or started card, a running job, a block that is not one kit publish command, a draft whose sha256 differs from `draft-sha:`), refuses unless the list holds every block of the card, and marks the card `status: started`, so it is never offered or run again. Then run the approved commands in card order and quote each read-back. When every block succeeded, `pending.mjs done <card>`, which also archives its `draft:` when no other card names it. A card under "Started, not closed" stays there until its read-backs are checked and it is closed with `done` or `card-note --refuse`.
   - On `approve.reword`: the requested change goes into the job's note for this round, and its `card-note <card> --text "<why>" --refuse` comes only after that note went out (Round per job, step 3), so a refused rework is never stranded and the old card never runs after the draft is redone. On a `card-check` or `card-start` refusal that only says the job is still running or another live cockpit runs it, leave the card open. On any other `card-check` or `card-start` refusal, or a writer's refusal (pin, ledger or lock): before anything else `card-note <card> --text "<why>" --refuse`, and the reason goes into that job's note. Name the job or session that must redo it and which blocks already wrote. `approve.drop` → `pending.mjs done <card>`. `approve.hold` → `pending.mjs card-note <card> --text "<the approve.hold label>"`, which leaves the card open but held, so the per-prompt list stops asking it and the next session start asks it again.
   - Once no card names a job listed under "Jobs", run `node ${CLAUDE_PLUGIN_ROOT}/scripts/job.mjs close <job file> --if-finished` for a `done` one, which keeps a dev job whose PR is still open, and plain `close <job file>` for a `stopped` one. Both refuse and write nothing while the job's agent is still running, waiting or not yet started in a live cockpit session, or when its bound agent's record holds no cockpit pid, because any job can mark another job `done` or `stopped`. When it refuses, quote the refusal, tell the user why the job stays open, and do not close it. When it closes a job an older kit started, quote its line that the job's session is the user's to end.
3. **Questions.** Ask each card under "Questions" that is not yet shown as `(answered: …)` or `(job running)` as one question, its option lines as the options in card order (the first is the recommended one and gets `(Recommended)`) and their consequences as the descriptions. A card whose options are the `run.none`, `run.lint` and `run.all` labels is a review job's run question: ask it with header `run.header` and its question text as written, naming the one head sha, so the hook records an approving answer for that sha. When the card names a job, follow `${CLAUDE_PLUGIN_ROOT}/shared/jobs.md` Cockpit 5 and 6: a card asking to start another role's job starts it on yes; every other answer goes back in one note file per job, holding all of that job's answers from this round, through one `job.mjs resume` per job, in the order below. A card that names no job: `card-note` the label.
   - **Round per job.** Once this round's answers are in, take each job in turn. First run every card of that job that got `approve.all`: its `card-start` and its writes (step 2). Then one `job.mjs resume` per job, with one note file holding every answer, reword and refusal reason for that job, and the SendMessage or Agent call it prints. Only after that call went out, `card-note` each answered card with its label and `pending.mjs done` it, and `card-note --refuse` each reworded card. When `card-check` or `card-start` refuses only because the job is still running or another live cockpit runs it, leave the card open and do not refuse it, so it is asked again. When `resume` refuses because the job is closed, has no launch record or has lost its folder, quote it and `card-note --refuse` each card of that job with that reason, since no answer can reach it. When it refuses because the job's agent is still running, waiting or starting, or another live cockpit runs it, leave every card of that job as it is, unanswered, so it is asked again once the agent is idle.
4. **Notices.** One `multiSelect` question listing the cards under "For your information" (up to four options per question); `pending.mjs done` each one the user picks.
5. **Done.** For `done <file>`: confirm the item was posted, sent, applied or dropped (the posting tool's output, a comment list or a tracker read-back), then `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs done <file>` and report the `archived:` path. Done when the file sits under `plans/archive/` and `MOVES.tsv` has its line.
6. **Stub.** For an item with no file and no git trace (a message the user must send, a call to make): `node ${CLAUDE_PLUGIN_ROOT}/scripts/pending.mjs stub "<action>"`. Done when the printed file exists.

## Done

The reply quotes the current list, every archived, stubbed or noted file path is named, and every command run from a card has its read-back quoted.
