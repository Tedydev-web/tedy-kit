tedy-kit

Plugin Claude Code mang cách làm việc của anh (review PR, làm task, vai PM) vào mọi phiên và mọi dự án. Cài một lần, tự nạp ở mọi phiên mới.

1. Phần tự chạy: anh không cần gõ gì

17 luật làm việc

File rules/working-style.md nạp vào mọi phiên qua ~/.claude/CLAUDE.md.

  • Xưng "em", gọi "anh".
  • Mọi thứ đăng dưới tên anh đều qua draft trước, đăng sau khi anh duyệt.
  • Không push hay mở PR khi chưa được bảo. "Noted lại cho tôi biết" nghĩa là chỉ báo cáo.
  • Không viết comment trong code.
  • PRD, Figma và BE lệch nhau thì nêu ra ngay, trích cả hai bên.
  • Cần anh quyết thì hiện menu chọn, không hỏi bằng văn xuôi.

Gate tự chặn

  • Sửa file mà thêm comment vào code: bị chặn.
  • git commit hoặc push khi diff có comment mới, hoặc cây chưa sạch: bị chặn.
  • Ghi thẳng lên GitHub (gh pr review, merge, close…): bị chặn. Đăng chỉ đi qua script sau khi anh duyệt.
  • Kết lượt bằng câu hỏi văn xuôi: em bị nhắc phải chuyển thành menu.

Luôn hỏi trước khi ghi ra ngoài

Các lệnh sau luôn hiện prompt để anh bấm cho phép, kể cả ở chế độ bypass:

  • push, tạo PR, merge
  • đăng hoặc trả lời comment GitHub, Figma, Google Doc
  • apply task lên OpenProject

Biết sẵn dự án

Map ở projects/: tonpass Family Wallet và TONtv. Mở phiên trong thư mục dự án là kit biết các repo, repo nào chỉ đọc, PRD tab nào, Figma node nào và tracker nào. Anh không cần dán link.

3. Luồng hằng ngày

Review PR của đồng đội

Anh: "review PR 703"→ Em đọc diff, PRD, Figma, BE→ Draft + lint→ Menu Đăng review: đăng / bỏ bớt / sửa / chưa đăng→ Đăng, đọc lại, báo K/K

Làm PM cho một use case

Anh: /tedy:pm UC_SW_02→ Ledger chỗ lệch→ Draft comment Figma/Doc + task OP, preview trên OP→ Menu Duyệt→ Đăng, đọc lại, báo id

Có review của Gemini trên PR của anh

Anh: /tedy:dev rebut + dán review→ Kiểm từng claim với code, PRD, dependency→ Bảng Đúng / Sai→ Menu Sửa gì→ Chỉ sửa phần anh chọn
Một phiên, một vai. Phiên PM là phiên duy nhất ghi lên OpenProject, Doc và Figma. Phiên Dev hay Review gặp việc PM thì để lại draft trong plans/reports/ và chuyển sang phiên PM.

5. Khi bị chặn

Thông báo bắt đầu bằngNghĩa là gì, làm gì
tedy gate: this edit adds comments to …Em vừa định thêm comment vào code. Em sẽ tự viết lại không có comment; phần giải thích đưa vào commit message.
tedy gate: the code being committed/pushed adds commentsDiff có comment mới. Nếu đó là comment của đồng đội cần giữ, anh tự chạy lệnh bằng ! git ….
tedy gate: tracked files have uncommitted changesCây chưa sạch. Commit hoặc khôi phục các file đó rồi push.
tedy gate: publish to GitHub through github-write.mjs …Đăng lên GitHub chỉ đi qua draft đã duyệt. Bảo em "đăng draft".
tedy gate: merging, closing or editing a PR … belongs to the userMerge, close, resolve là việc của anh, em không làm thay.
Prompt cho phép khi push/đăng/applyĐó là bước chốt cuối cùng. Bấm cho phép nếu đúng là anh muốn ghi ra ngoài.

6. Bảo trì

  • Kit chạy thẳng từ ~/Documents/workspace/tedy-kit. Sửa kit thì mở phiên mới hoặc gõ /reload-plugins.
  • Dòng @~/Documents/workspace/tedy-kit/rules/working-style.md phải luôn có trong ~/.claude/CLAUDE.md.
  • Sau mỗi lần Claude Code tự cập nhật: bash evals/probes/run-probes.sh.
  • Test của kit: node --test plugin/scripts/*.test.mjs.
  • Chưa có: neo comment vào đoạn văn trong Google Doc cần một OAuth client riêng. Trước khi có, câu hỏi PRD nằm trong file HTML để anh tự đăng.
Muốn đổi một luật, một mẫu comment hay thêm dự án: nói với em trong phiên làm kit, hoặc chạy /tedy:learn. Không cần sửa file tay.
