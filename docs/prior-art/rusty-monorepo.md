# TrogonStack/rusty-monorepo

A supplement of sweep 261021-canon, not reference-labelled: the `trg` CLI in `crates/trg`, whose `ai skills eval iteration-summary` compares a baseline and a candidate eval run of the same suite on pass rate and on cost, duration and total tokens per run, studied for S32 (technique T5) because it fails a change whose cost or tokens rise beyond the noise the runs themselves measure, though every gate is opt-in through `--fail-on`, a first iteration with no previous report always exits 0, the token metric leaves out cache reads and writes, and it has no no-plugin arm; the kit lines cited below are the uncommitted T5 work in the worktree on 2026-10-30.

## Issues and changelog
The repository has no closed issues. Its merged PRs carry two or three comments each, so that sort says little and the three below were chosen for their S32 relevance, not by that sort. `crates/trg/CHANGELOG.md` lists them at lines 58, 60 and 83.
- https://github.com/TrogonStack/rusty-monorepo/pull/268 "Totals cannot settle the question. Two bundles that drew a different number of runs, or one runaway run, differ in total for reasons that are not the change."
  - Broke: the keep-or-revert verdict read pass rates only, so a change that kept its pass rate but cost more per run, ran slower or spent more tokens read as `keep` and CI could not catch it. Fixed: per-run cost, duration and token verdicts on a 95% interval, a tolerance per metric, and the `cost_regression`, `latency_regression` and `token_regression` gates in `--fail-on`, which leave the recommendation unchanged.
- https://github.com/TrogonStack/rusty-monorepo/pull/222 "The intervals already existed, but keeping only what beats the noise was a judgment each author made differently."
  - Broke: whether a change cleared the noise was left to each author, and CI had no way to refuse a regression without a human reading the numbers. Fixed: the recommendation keeps only a change that beats the noise, flags overfitting, and `--fail-on` turns it into an exit code.
- https://github.com/TrogonStack/rusty-monorepo/pull/229 "A missing or corrupt `--previous` made the CI gate pass, so a broken invocation looked like a clean one."
  - Broke: the gate failed open when the previous report could not be read. Fixed: an unreadable previous report exits 3 (reference line 527); only an absent one still exits 0 (iteration_summary.rs lines 19-20).

## Lessons
- Judge a cost or token rise on an interval built from the runs themselves, not on a band measured once beforehand (S32, Q25): reference lines 481-492, efficiency.rs lines 278-279. Touches plugin/lib/eval-baseline.mjs:28 (`costTolerance`, 2·sd/mean/√n measured from repeated runs of one cell through `rebaseline.mjs --noise`) and :46 (a cell's mean against the baseline mean times the band); partial; medium cost. trg needs four completed runs per side and the kit draws `RUNS=3` per cell (plugin/evals/pressure/run-pressure.sh:6), so adopting the interval means 4 runs per cell and a port of shift.rs (287 lines with tests, which pin the ranks against the published table at line 174).
- Leave a run that did not complete out of the cost arm (S32, Q24): efficiency.rs lines 220-222, reference lines 499-500. Touches plugin/lib/eval-baseline.mjs:18-21 (`tally` averages the cost of every run, including one stopped by `--max-budget-usd 1`, `--max-turns 30` or `timeout 600` at plugin/evals/pressure/run-pressure.sh:139); gap; low cost once plugin/evals/pressure/grade-pressure.mjs records the `result` event's `subtype` (line 65 writes its `total_cost_usd` and `usage`, not how it ended).
- An unpriced run is unmeasured, never free (S8, Q24): reference lines 502-503. Touches plugin/lib/eval-baseline.mjs:41-43 (refuses a cell whose `costRuns` is below `runs`); overlap.
- Both fail open on a first run: no previous report means exit 0 whatever `--fail-on` says (iteration_summary.rs lines 19-20), as the kit skips a cell with no baseline cost (plugin/lib/eval-baseline.mjs:40) and no baseline cell (:61) (S32, Q25); overlap; none, but a kit check that claims to fail every artifact would have to fail a cell that has no baseline yet instead of passing it.
- A missing or unreadable baseline file is an error, not a pass (Q25): PR 229, reference line 527. Touches plugin/evals/pressure/rebaseline.mjs:16 (a missing `baseline.json` becomes `null` and every cell is new); partial; low cost.
- Gate tokens as well as cost, and say which tokens (Q24, Q25): claude_code.rs lines 292-294 gate input plus output only, so a broken cached prefix, which moves cache-creation tokens, never trips `token_regression` on claude-code; only the cost verdict sees it (DERIVED from the fixture and `total_cost_usd` at line 256). Touches plugin/evals/pressure/grade-pressure.mjs:64 (records input, cacheWrite, cacheRead and output per run) and plugin/lib/eval-baseline.mjs:35-52 (gates cost only); gap; low cost to gate cache writes from the split the kit already records.
- Not covered: the no-plugin arm of docs/adr/0009-fact-based-ablation-evals.md:14 (trg's arms are baseline and candidate iterations of the same skill), any static check on a kit artifact (every verdict needs paid runs), and every gate is opt-in through `--fail-on`, with a default tolerance of 0.
