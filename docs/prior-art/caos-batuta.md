## Lessons
- A red counts only when one of the new tests fails by its own name: exit 0, zero tests run, or another test's failure is not red (L322-L327): touches `plugin/skills/dev/SKILL.md:35` (Build has no Red step) and `:39` (report records the red output); gap; cost low, a skill clause run in-session before the first source edit.
- History replay: each `[red]` commit is checked out in a neutrally named temporary worktree and its new tests must fail there (L46, L325): touches `plugin/skills/dev/SKILL.md:36-37`; gap; cost high, and it needs the tests in git history.
- `[red]`/`[green]`/`[refactor] T-NNN` commit grammar, green without an earlier red fails, red holds tests and the lock only: touches `plugin/skills/dev/SKILL.md:36` (message per `commit-pr.md`); gap; cost medium, and it changes team-facing commit subjects.
- Zero tests is not green, in the red run and the verify run (L327, L494): touches `plugin/skills/dev/SKILL.md:37` and `plugin/shared/source-access.md:51`; gap, overlaps the nizos-tdd-guard card; cost low, require a non-zero count of tests run in the verify output.
- Locked test files: hash the test files at red, deny later edits except through a human-approved change request (locked_tests.py L4, L9; hooks.json L46-L50): touches `plugin/skills/dev/SKILL.md:37` and `plugin/hooks/hooks.json:11-13` (role-gate is the same PreToolUse shape); gap; cheap form low (hash after the red run, compare at verify, report drift), full deny-guard high (Batuta needs a shell parser across many spellings and still leaks via F-24).
- Weakening detector: a skip, only or todo marker added, an assertion count that drops, or a changed test-collection config fails unless approved (L1080-L1086; JS list at test_markers L23-L24; configuration can only add markers, L639): touches `plugin/skills/dev/SKILL.md:37` and `plugin/agents/reviewer.md:31` (local tests are outside every diff the reviewer reads); gap; cost low to medium, a regex count over the local test files at red and at verify; Batuta reads only pytest settings files for deselection, so vitest or jest `exclude` and `passWithNoTests` are not covered by its design.
- Locked-test runtime presence: every test locked at red must appear as run and passed in the verify run, not skipped, deselected or expected-failure, whatever config, hook or import caused it (L1246, L1198): touches `plugin/skills/dev/SKILL.md:37`; gap; cost medium (per-test output from the runner's JSON or JUnit reporter); the strongest P2 form because it checks the run, not the source.
- Result tally consistency: per-test result lines must equal the runner's own summary counts (L489, L499): touches `plugin/skills/dev/SKILL.md:37`; gap; cost medium (parsers only for unittest verbose, pytest `-rA` and JUnit XML); it defends against forged output, not against an agent weakening tests.
- Runner forgery scan: an AST scan for runner patches, stdout or stderr replacement, parent-process reads and non-literal `exec` (test_markers L556, tdd_history L898): touches nothing in the kit; gap; cost high (Python-only; the kit's repos are TypeScript frontends, `plugin/skills/dev/SKILL.md:10`); the author records the in-process residual as accepted (#12).
- Tests written by a separate agent from the code (red SKILL L10): touches `plugin/skills/dev/SKILL.md:35` and `:38` (the kit already spawns `tedy:reviewer`); gap; cost medium, a test-author subagent before Build.
