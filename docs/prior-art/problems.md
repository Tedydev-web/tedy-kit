# Problem registry: dev role

A problem is one behaviour a role step must get right. Problems are listed top-down from a fixed frame, so mechanisms are searched per problem instead of collected from sources. Generic names only; client facts stay in the profile.

## Frame

- SWEBOK Guide V4 knowledge areas (IEEE Computer Society: "Its 18 knowledge areas (KAs) summarize key concepts"): Software requirements; Software architecture; Software design; Software construction; Software testing; Software engineering operations; Software maintenance; Software configuration management; Software engineering management; Software engineering process; Software engineering models and methods; Software quality; Software security; Software engineering professional practice; Software engineering economics; Computing foundations; Mathematical foundations; Engineering foundations.
- ISO/IEC/IEEE 12207:2026 process groups: agreement; organizational project-enabling; technical management; technical.
- Dev steps (numbered items of `plugin/skills/dev/SKILL.md`): 1 Context; 2 Reconcile; 3 Branch; 4 Build; 5 Commit; 6 Verify on the commit; 7 Independent review; 8 Draft PR, report and next step.
